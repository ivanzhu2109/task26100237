# conflictcheck

会议排期冲突检查库（纯内存、无外部依赖），供上层发布流程在排期发布前直接调用。

## 冲突规则

两个场次满足以下两条即构成冲突：

1. 时间区间存在正时长交集（`StartMs < 对方.EndMs` 且 `EndMs > 对方.StartMs`；
   一个场次结束的瞬间允许另一个开始）；
2. 占用同一房间，或拥有至少一名共同讲者。房间与讲者是不同资源类型，
   标识值相同不代表同一资源；赛道不同不豁免冲突。

冲突以无序场次对为单位，同一对只报告一次，并列齐该对共享的房间与全部共享讲者。

## 输入约束

- 每场：唯一正整数 `ID`、一个 `Room`、最多 8 名互不重复的 `Speakers`、
  `StartMs < EndMs`（UTC 毫秒时间戳）。
- 单份排期支持 10 万场次；输入非法时 `NewChecker` 返回错误。
- 不处理版本编辑；检查期间请勿修改输入。

## 用法

```go
checker, err := conflictcheck.NewChecker(sessions) // 校验并构建检查状态
if err != nil { /* 输入非法 */ }

for {
    batch, done := checker.Next(100) // 按 (FirstID, SecondID) 升序分段读取
    for _, c := range batch {
        // c.FirstID < c.SecondID；c.Room 为共享房间（无则 ""）；
        // c.Speakers 为全部共享讲者（升序，无则 nil）
    }
    if done { break } // 可随时停止；分段读取与一次读完内容一致
}
```

- 报告按（较小场次 ID，较大场次 ID）升序交付，与输入排列无关。
- 不预先返回冲突总数；`done` 为 true 表示报告已全部交付。
- `Checker` 不是并发安全的。

## 性能

- 任意排期从开始检查到交付前 100 条冲突 < 5 秒（实测约 0.16 秒，
  含约 5×10^9 对冲突的高密度场景）。
- 冲突不超过 1000 对的 10 万场次排期，完整读取 < 5 秒（实测约 0.14 秒）。
- 输入 + 检查状态 + 未交付结果的峰值堆内存 < 256 MiB（实测约 80–120 MiB）。

实现要点：按资源（房间/讲者）建立静态区间索引（按开始时间排序 + maxEnd
线段树剪枝），查询代价 O(log n + k)；报告按场次 ID 顺序惰性展开，
冲突对仅在交付前按当前前者小批量缓冲，因此数十亿对的报告也不会撑爆内存。
