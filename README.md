# confcheck

会议排期冲突检查库（纯内存，无外部服务依赖），供上层发布流程在发布前调用。

## 规则

- 输入为单个会议的一份完整待发布排期：每个场次有唯一正整数 ID、一个房间、
  最多 8 名不同讲者、开始/结束 UTC 毫秒时间戳（开始严格早于结束）。
- 两个场次共享房间或有共同讲者，且时间区间存在正时长交集，即构成冲突；
  端点相接不算冲突。房间与讲者是不同资源类型，标识值相同不互通。
- 冲突按无序场次对报告，每对仅一条，包含全部共享房间与全部共享讲者。
- 报告按 (较小 ID, 较大 ID) 升序交付，与输入排列无关。

## 调用方式

```go
checker, err := confcheck.NewChecker(sessions) // 校验输入并构建内存索引
if err != nil { /* 输入非法 */ }

it := checker.Conflicts()   // 惰性迭代器，可分段读取，可随时停止
for {
    cf, ok := it.Next()     // ok == false 表示报告结束
    if !ok { break }
    // cf.A < cf.B；cf.Rooms 为共享房间（0 或 1 个）；cf.Speakers 为全部共享讲者
}
```

- 冲突惰性计算：即使完整报告有数十亿对，前 100 条也能快速交付，不预先计算总数。
- 同一 `Checker` 可创建多个迭代器；每个迭代器独立、有序、不重不漏。
- 10 万场次下：稀疏（≤1000 对）完整报告与高密度场景首批交付均在毫秒级，
  输入 + 检查状态 + 未交付结果的堆内存远低于 256 MiB。
